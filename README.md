# Паравозики: блоки как вагончики, дела как пассажиры

Открытое приложение для планирования недели по блокам: **неделя → корректировка → фокус → итоги**. Основной экран рассчитан на компьютер, интерфейс адаптирован для телефона.

## Запуск

Нужен Node.js 22 или новее. Установите зависимости командой `npm ci`. Для локального сервера нужен Node.js 22.13 или новее (встроенный SQLite).

```sh
npm ci
npm start
```

Откройте http://127.0.0.1:4173 и зарегистрируйте аккаунт с email и паролем от 12 символов. Пароли не передавайте в GitHub или чат. Проверки: `npm test` и `npm run check`.

Интерфейс находится в `dist/`, сервер аккаунтов — в `server/api.js`. Для регистрации и синхронизации нужен сервер: GitHub Pages не выполняет API. `npm run build` собирает Cloudflare Worker со встроенным интерфейсом; D1 подключается как `DB`. Схема базы — в `drizzle/0000_accounts.sql`. При открытии через `file://` JavaScript-модули могут блокироваться: используйте HTTP-сервер.

## Первый проход

1. Откройте настройки и проверьте блоки: Грамота, Альянс, Life Admin, LP.
2. Добавьте недоступное время. В неделе создайте интервалы и сохраните шаблон.
3. Нажмите название блока в календаре или откройте «Блоки», чтобы увидеть все его задачи. Фильтры: «Сегодня», «Неделя» (открытая в календаре), «Все». Задачи сгруппированы по датам; видны статус и план/факт. Добавьте задачи через пошаговую форму. В корректировке перенесите перегрузку.
4. Откройте сегодняшний день, запустите день и фокус-сессию.
5. Заполните самооценки и комментарий в итогах.

Шаблон понедельника/вторника заполнен как пример. Реальных задач в поставке нет.

## Статус 0.1

Работают регистрация, вход/выход, серверное сохранение плана отдельно для каждого аккаунта, экспорт/импорт JSON, интервалы, ограничения, шаблон, ручные переносы, помодоро и отчёт. **Telegram ещё не подключён**: пошаговая форма показывает будущий диалог. План загружается из аккаунта при входе и перезагрузке. Одновременные изменения защищены проверкой версии: конфликт требует обновить страницу. Локальная копия страхует несохранённые изменения. Работа нескольких активных таймеров на разных устройствах пока не координируется. Фоновый таймер восстанавливает длительность по часам, но браузер не гарантирует своевременное предупреждение в спящей вкладке; после пробуждения проверка выполняется снова.

Остановка таймера сохраняет факт сессии; завершение задачи отдельно отмечает её готовность. Переносы не изменяют baseline, зафиксированный при запуске дня. При исчерпании блока таймер приостанавливается: завершите сессию и вручную скорректируйте интервалы/оставшиеся задачи.

Полное согласованное ТЗ и границы этапов: [docs/SPECIFICATION.txt](docs/SPECIFICATION.txt).

## Структура

- `dist/model.js` — календарь, расчёт бюджета, снимок плана, история переносов.
- `dist/app.js` — интерфейс и управление состоянием.
- `tests/model.test.mjs` — проверки правил времени и истории.
- `server.mjs` — локальная раздача файлов, без API и внешнего доступа.

## Аккаунты и безопасность

Bcrypt с cost=12, случайные сессии на 7 дней, хеши токенов в базе, HttpOnly/SameSite=Strict cookie (Secure на HTTPS), проверка Origin на изменяющих запросах и ограничение попыток входа. Каждый план принадлежит одному внутреннему user ID. Пароли длиннее 72 UTF-8 байт отклоняются без усечения.

Подтверждение email и восстановление забытого пароля пока не подключены: для них нужен отдельный почтовый сервис. Сохраните пароль в менеджере паролей. Платформенный вход ChatGPT на текущем хостинге сохраняется как внешний уровень ограничения доступа; открытый GitHub не делает личные планы публичными.

Локальная база `.data/paravoziki.sqlite` и резервные копии не входят в Git. Перед миграциями делайте резервную копию базы; применённые SQL-миграции не изменяйте. На хостинге миграции применяются при развёртывании.
