# Паравозики: вагончики как вагончики, дела как пассажиры

Открытое приложение для планирования недели по вагончикам: **неделя → корректировка → фокус → итоги**. Основной экран рассчитан на компьютер, интерфейс адаптирован для телефона.

## Запуск

Нужен Node.js 22 или новее. Установите зависимости командой `npm ci`. Для локального сервера нужен Node.js 22.13 или новее (встроенный SQLite).

```sh
npm ci
npm start
```

Откройте http://127.0.0.1:4173 и зарегистрируйте аккаунт с email и паролем от 12 символов. Пароли не передавайте в GitHub или чат. Проверки: `npm test` и `npm run check`.

Интерфейс находится в `dist/`, сервер аккаунтов — в `server/api.js`. Для регистрации и синхронизации нужен сервер: GitHub Pages не выполняет API. `npm run build` собирает Cloudflare Worker со встроенным интерфейсом; D1 подключается как `DB`. Схема базы — в `drizzle/0000_accounts.sql`. При открытии через `file://` JavaScript-модули могут блокироваться: используйте HTTP-сервер.

## Первый проход

1. Откройте настройки и проверьте вагончики: Грамота, Альянс, Life Admin, LP.
2. Добавьте недоступное время. В неделе создайте интервалы и сохраните шаблон.
3. Нажмите название вагончика в календаре или откройте «Вагончики», чтобы увидеть все его задачи. Фильтры: «Сегодня», «Неделя» (открытая в календаре), «Все». Задачи сгруппированы по датам; видны статус и план/факт. Добавьте задачи через пошаговую форму. В корректировке перенесите перегрузку.
4. Откройте сегодняшний день, запустите день и фокус-сессию.
5. Заполните самооценки и комментарий в итогах.

Шаблон понедельника/вторника заполнен как пример. Реальных задач в поставке нет.

## Статус 0.1

Работают регистрация, вход/выход, серверное сохранение плана отдельно для каждого аккаунта, экспорт/импорт JSON, интервалы, ограничения, шаблон, ручные переносы, помодоро и отчёт. Telegram подключается в настройках через токен собственного бота из BotFather. После подключения нужно привязать личный чат по одноразовой ссылке. План загружается из аккаунта при входе и перезагрузке. Одновременные изменения защищены проверкой версии: конфликт требует обновить страницу. Локальная копия страхует несохранённые изменения. Работа нескольких активных таймеров на разных устройствах пока не координируется. Фоновый таймер восстанавливает длительность по часам, но браузер не гарантирует своевременное предупреждение в спящей вкладке; после пробуждения проверка выполняется снова.

Остановка таймера сохраняет факт сессии; завершение задачи отдельно отмечает её готовность. Переносы не изменяют baseline, зафиксированный при запуске дня. При исчерпании вагончика таймер приостанавливается: завершите сессию и вручную скорректируйте интервалы/оставшиеся задачи.

Полное согласованное ТЗ и границы этапов: [docs/SPECIFICATION.txt](docs/SPECIFICATION.txt).

## Структура

- `dist/model.js` — календарь, расчёт бюджета, снимок плана, история переносов.
- `dist/app.js` — интерфейс и управление состоянием.
- `tests/model.test.mjs` — проверки правил времени и истории.
- `server.mjs` — локальная раздача файлов, без API и внешнего доступа.

## Аккаунты и безопасность

Bcrypt с cost=12, случайные сессии на 7 дней, хеши токенов в базе, HttpOnly/SameSite=Strict cookie (Secure на HTTPS), проверка Origin на изменяющих запросах и ограничение попыток входа. Каждый план принадлежит одному внутреннему user ID. Пароли длиннее 72 UTF-8 байт отклоняются без усечения.

Подтверждение email и восстановление забытого пароля пока не подключены: для них нужен отдельный почтовый сервис. Сохраните пароль в менеджере паролей. Публичный интерфейс размещается на GitHub Pages: https://abonch.github.io/paravoziki/. Сервер аккаунтов работает отдельно; личные планы доступны только с действующей сессией. Внешний вход ChatGPT для GitHub Pages не требуется.

Локальная база `.data/paravoziki.sqlite` и резервные копии не входят в Git. Перед миграциями делайте резервную копию базы; применённые SQL-миграции не изменяйте. На хостинге миграции применяются при развёртывании.

## GitHub Pages

`npm run build:pages` готовит интерфейс в `docs/`. В настройках Pages выбраны ветка `main` и папка `/docs`. После изменения интерфейса выполните сборку и закоммитьте обновлённые `docs/`.

`docs/config.js` содержит публичный адрес API (не секрет). Сервер разрешает браузерные запросы только с точного origin из `PUBLIC_APP_ORIGIN=https://abonch.github.io`. При внешнем входе случайный токен сессии хранится в `sessionStorage` вкладки; при закрытии вкладки может потребоваться повторный вход. Токен не включается в URL и никогда не попадает в репозиторий.

## Telegram

Настройки → Telegram → Подключить Telegram-бота. Вставьте токен BotFather только в поле приложения. Затем откройте одноразовую ссылку и нажмите Start. Ссылка действует 10 минут. Бот принимает задачи только от привязанного Telegram user ID и только в личном чате.

Бот спрашивает вагончик, длительность, день/дату и подтверждение. Поддерживает кнопки, собственную длительность и календарь. Команды `/new`, `/today`, `/cancel`, `/help`. После добавления задачи обновите план в приложении. Изменения из Telegram увеличивают версию плана: устаревшая вкладка не сможет затереть их.

Серверный `BOT_ENCRYPTION_KEY` — 32 случайных байта в hex, задаётся как секрет окружения; не меняйте его без миграции зашифрованных токенов. Локальный сервер создаёт ключ в `.data/bot-key`, исключённом из Git. Токены шифруются AES-GCM, webhook проверяет секретный заголовок, входящие обновления и подтверждения обрабатываются идемпотентно. Подключение заменяет прежний webhook выбранного бота. Не используйте один и тот же бот для разных сервисов.

## Входящие и задачи из бота

«Входящие» показывают незавершённые задачи за все даты: отдельно без интервала своего вагончика и не помещающиеся в его дневной бюджет. Счётчик виден в меню. Можно выделить время, перенести задачу или открыть все дела её вагончика. Добавление достаточного интервала или перенос в подходящий день убирает дело из входящих. При нехватке времени задачи рассматриваются в порядке добавления.

В разделах «Неделя», «Вагончики» и «Входящие» приложение проверяет новые версии плана каждые 15 секунд и при возврате во вкладку. Новые данные подгружаются автоматически, если нет несохранённых изменений, открытого диалога или активной сессии. Во время редактирования и таймера показывается уведомление; есть кнопка «Обновить задачи». Несохранённая работа не перезаписывается.

## Ручное планирование, вагончики и накопитель

Сверху недели находится запас вагончиков всех ваших категорий. Цвет и подпись берутся из настроек. Перетаскивание в день недели открывает создание нового интервала (по умолчанию 2 часа); источник остаётся в запасе. Серый вагончик создаёт недоступное время на 1 час с обязательной подписью. Начало и длительность можно изменить; защищённое время и существующие интервалы учитываются при выборе свободного начала. Нажатие на вагончик — альтернатива перетаскиванию для телефона и клавиатуры.

Задачи перетаскиваются на карточки существующих вагончиков или размещаются кнопкой «В вагончик». При выборе другого вагончика меняются категория и дата, история фактических сессий сохраняется. При нескольких интервалах одной категории ручной выбор закрепляет задачу за выбранным интервалом; бюджет остаётся суммарным по категории за день. При превышении бюджета приложение запрашивает подтверждение, а не поместившаяся работа остаётся во входящих.

«Накопитель» содержит задачи без даты отдельно от расписания. В боте выберите «В накопитель — без даты» на шаге выбора дня; команда `/backlog` показывает список. В приложении можно создать такую задачу в накопителе, перенести туда уже запланированную или назначить ей дату/вагончик. Планы старого формата без массива `backlog` продолжают работать.

«Удалить» убирает задачу из текущего списка. В уведомлении доступно «Отменить удаление». Фокус-сессии и исходные снимки плана не удаляются. При удалении активной задачи текущая сессия сначала фиксируется.

### Личные аккаунты и календарь

Новый аккаунт начинает с пустого расписания и тремя переименовываемыми категориями «Вагончик 1», «Вагончик 2», «Вагончик 3». Серый вагончик «Занятое время» доступен сразу. Планы, подключения Telegram и календаря принадлежат отдельным аккаунтам.

Вагончики можно переносить мышью вместе с делами и растягивать за левый или правый край с шагом 15 минут. Пересечения с другими интервалами и занятым временем отклоняются. Прошедшее время закрыто для новых интервалов и новых дел; новые дела из Telegram для уже закончившихся вагончиков попадают во входящие.

Google Calendar подключается в «Настройках» через секретную iCal-ссылку. Ссылка хранится на сервере зашифрованной ключом `BOT_ENCRYPTION_KEY`, не включается в экспорт или ответы API. Импорт односторонний: события отображаются как занятое время, изменения выполняются в Google Calendar. Поддерживаются повторения, исключения, отмены, события на весь день, переходы через полночь и часовые пояса. Обновление выполняется при открытии приложения, смене отображаемой недели и каждые пять минут, пока приложение открыто. При ошибке сохраняется последняя успешная копия. Для календаря применяется миграция `drizzle/0002_google_calendar.sql`.

### Единый накопитель

Раздел «Входящие» объединён с накопителем. Новые дела из приложения и Telegram по умолчанию сохраняются без даты. Уже существующие нераспределённые и не поместившиеся дела показываются там же, без изменения истории. Форма быстрого добавления находится над шкалой часов; счётчики неразобранных дел и значок обновления — над накопителем. Дело можно сохранить без вагончика: оно отображается белым.

Крестик у импортированного события Google Calendar скрывает локальную копию, не удаляя оригинал в Google. Скрытые копии не восстанавливаются при очередной синхронизации.

Imported calendar occurrences support local title, category/color and duration edits. calendarOverrides are account-scoped, sanitized and reapplied after each iCal sync; Google Calendar is never modified. Edits apply to the selected occurrence only.
