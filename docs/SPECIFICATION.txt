РИТМ — ТЕХНИЧЕСКОЕ ЗАДАНИЕ
Версия 1.0 · 17 ноября 2026

1. ЦЕЛЬ И АУДИТОРИЯ
Открытое приложение для личного управления временем. Основной сценарий — работа на компьютере, дополнительный — телефон. Цикл: Weekly Planning → Adjusting → Day Tracking → итоги. Личный план и данные не становятся публичными из-за открытого исходного кода. Пользователь сохраняет контроль над изменениями; агент может предлагать, но не применять переносы без подтверждения.

2. СОГЛАСОВАННАЯ МОДЕЛЬ
Блок — именованное направление деятельности: Альянс, Грамота, Life Admin, LP. Интервал — конкретное время блока в определённую дату. У блока может быть несколько интервалов за день и неделю. Пример: понедельник утром Грамота 4 часа, затем Life Admin; вторник — LP и Альянс. Интервалы не могут пересекаться между собой и с недоступным временем. План может содержать свободное время; заполнять все часы необязательно.
Настройки блоков, повторяемый шаблон недели, план конкретной недели и неизменяемый исходный план запуска дня — отдельные сущности. Изменения конкретной недели не переписывают шаблон. Переносы не переписывают исходные оценки и историю.

3. НАВИГАЦИЯ
Неделя: календарь, интервалы, задачи, нагрузка, применение шаблона, корректировка.
Мой день: текущий план, запуск дня, задачи, помодоро.
Итоги: план/факт, выполнение, переносы, причины, самооценки.
Настройки: Telegram, блоки, недоступное время, шаблон, данные и часовой пояс.

4. НАСТРОЙКИ
4.1 Блок: название, цвет, уникальный Telegram-тег. В полной версии — целевые часы в неделю, предпочтительные окна, минимальный интервал, разрешение двигать/сокращать и нижняя граница времени. Создание, редактирование, архивирование с сохранением истории.
4.2 Недоступное время: название, начало, длительность, часовой пояс. Разовое событие или еженедельное повторение по дню недели с началом и необязательной датой окончания. Временный курс — повторение с датой окончания. После окончания события больше не блокируют время. Полная версия: несколько дней недели, буферы до/после, отмена/изменение отдельного вхождения, необязательная привязка к блоку для отчётности без двойного учёта.
4.3 Telegram: личный чат с ботом как базовый вариант; канал — возможное расширение. Статус подключения, привязка Telegram user ID к владельцу плана, отключение, диагностика. Токен только на сервере, вне исходного кода, экспортов, браузера и логов.

5. WEEKLY PLANNING
Выбор недели; добавление, изменение и удаление интервалов. Сохранение недели как шаблона и применение к другой неделе. Существующие задачи не удаляются. Повторное применение не создаёт точные дубликаты. Конфликты применения должны быть показаны до подтверждения. Создание задач с названием, блоком, оценкой и конкретной датой. Задача без подходящего интервала остаётся видимой как требующая корректировки. План/загрузка показываются по блоку за день. При нескольких интервалах один бюджет равен их сумме; задачи не дублируются.

6. TELEGRAM: ДОБАВЛЕНИЕ ЗАДАЧИ
Пользователь отправляет название. Бот спрашивает:
1) блок — кнопки из актуальных настроек;
2) длительность — 15, 30, 45, 60, 90, 120 минут или собственное положительное число;
3) день — сегодня, завтра, день недели с конкретной датой либо произвольная дата через календарь;
4) подтверждение — название, блок, оценка, дата; Добавить / Изменить / Отмена.
На каждом шаге Назад и Отмена. Черновик сохраняется на сервере, поддерживается восстановление. Новое сообщение при активном черновике требует выбора: новая задача или продолжить старую. При сообщении с однозначными полями бот запрашивает только недостающие; неоднозначное значение требует уточнения. Свободный текст не должен самостоятельно создавать переносы.
Перед подтверждением бот показывает оставшийся бюджет. При перегрузке/отсутствии интервала: другая дата или сохранение с явным флагом корректировки. После подтверждения одна задача создаётся ровно один раз: идемпотентность по update_id и callback; устаревшие кнопки не создают дубли. Бот работает только с авторизованным владельцем. Команды /start, /new, /cancel, /today, /help. Не использовать Telegram-канал как базу данных.

7. ADJUSTING
Проверка: интервалы против недоступного времени; интервалы между собой; остатки задач против свободного бюджета блока. Свободный бюджет = длительность интервалов минус уже потраченное в этом блоке время; потребность = сумма незавершённых остатков оценок. Завершённые задачи больше не требуют остатка, их фактическое время остаётся расходом.
Варианты: перенос задачи/остатка на дату с доступным интервалом того же блока; увеличение интервала за счёт свободного времени; изменение соседних блоков с переносом затронутых задач; уточнение объёма/оценки. Полная версия предлагает варианты и показывает весь набор последствий до подтверждения. Применение каскада — атомарно, с журналом и возможностью отмены. Защищённое время не занимается автоматически. Если подходящего места нет, приложение честно показывает нераспределённый остаток.
Запуск дня фиксирует исходный план и требует устранить перегрузки/пересечения. При последующих изменениях baseline остаётся прежним; поздно добавленные задачи отмечаются как незапланированные.

8. DAY TRACKING
Таймер запускается одной кнопкой рядом с задачей. Один активный таймер на пользователя на всех устройствах. Помодоро по умолчанию 25 минут; предложение перерыва 5 минут; длинный перерыв и настройка длительности — расширение. Пауза/продолжение/остановка, отметка готовности. Факт считается по временным меткам, а не числу срабатываний setInterval. Активная сессия переживает перезагрузку. Пауза исключается из факта. Свернутая вкладка не теряет время; точность системных уведомлений зависит от окружения. Полная версия: серверный статус, обработка смены даты/часового пояса, восстановление после сна и сверка длительной сессии с пользователем.
При исчерпании оценки задачи: предложить завершить, продолжить в пределах блока, перенести оставшиеся дела блока или остаток текущей задачи.
При достижении границы интервала или бюджета: остановить/приостановить таймер, показать задачи всех затронутых блоков. Продолжение требует обновить расписание; нельзя просто скрыть конфликт или увеличивать блок поверх защищённого события. В полной версии — единый экран решения с предпросмотром последствий и подтверждением. Возможное откладывание решения должно оставлять явный нерешённый конфликт, а не незаметно разрешать перерасход.

9. ИТОГИ ДНЯ
Общий отчёт: исходные плановые минуты, фактические минуты по сессиям дня, завершённые задачи, входящие/исходящие переносы, незапланированные дела. По каждому блоку: завершено из исходно запланированных; план/факт; перенесённый остаток; самооценка 1–5, необязательная. Комментарий и причина: скрытые дела, незапланированное, сложность, отвлечения, приоритеты, другое.
Большое расхождение предлагает комментарий без обязательного заполнения. Рабочее значение первой версии — абсолютная разница от 60 минут; в полной версии настраиваемый порог с учётом процента. Факт относится к дате и блоку выполнения, даже если задача позднее перенесена. План не переписывается задним числом. Счётчик переносов отличает уникальные задачи от событий переносов.

10. ДАННЫЕ И АРХИТЕКТУРА
Сущности: User, Category, WeeklyTemplate, TemplateInterval, ScheduledInterval, UnavailabilityRule, OccurrenceException, Task, TaskPlanSnapshot, FocusSession, MoveEvent, DayReview, CategoryRating, TelegramBinding, TelegramDraft, AuditEvent.
Task содержит исходную оценку/дату, текущую дату, статус и журнал переоценок; фактическое время выводится из FocusSession. Временные метки сессий UTC, календарные даты интерпретируются в IANA-часовом поясе владельца. Отдельные оценки, фактические минуты и остаток не смешиваются. Сервер проверяет принадлежность всех объектов текущему пользователю, валидирует интервалы и идемпотентность.
Этап 1: адаптивный браузерный клиент без зависимостей, локальное хранение, экспорт/импорт; развёртываемый статический интерфейс.
Этап 2: API, база данных, вход, серверная валидация, авторизация и синхронизация; только затем рабочий Telegram-бот.
Этап 3: подбор вариантов переноса, атомарные каскады, исключения повторений, расширенная аналитика и уведомления. LLM необязателен; базовые правила и таймер работают без модели.

11. ОТКРЫТЫЙ ПРОЕКТ И ЭКСПЛУАТАЦИЯ
Исходный код на GitHub, лицензия MIT, инструкция локального запуска и самостоятельного развёртывания. Секреты через переменные окружения сервера. Репозиторий и демо не содержат личных задач, реальных токенов и баз данных. Раздельные демо/личные данные. Экспорт, резервные копии, удаление аккаунта/данных и политика конфиденциальности до публичной серверной версии. Доступность с клавиатуры, подписи элементов, адаптивный интерфейс.

12. КРИТЕРИИ ПРИЁМКИ ПОЛНОЙ ВЕРСИИ
- Один шаблон создаёт нужную неделю, не меняя соседние недели и baseline.
- Четырёхчасовой блок корректно суммирует задачи и показывает превышение.
- Повторяющийся курс с конечной датой блокирует только свои вхождения.
- Бот проводит весь сценарий, возвращается назад и не дублирует подтверждение.
- Перенос показывает нагрузку целевого дня и сохраняет историю исходного дня.
- Расширение блока затрагивает соседние блоки только после подтверждения всего каскада.
- Таймер не теряет время при перезагрузке и не считает паузу.
- Выход за блок требует решения по всем затронутым блокам дня.
- Перенос после выполнения части задачи не переносит фактическое время в другой день.
- Отчёт после переносов сохраняет исходный план и допускает отдельные оценки по блокам.
- Данные одного пользователя недоступны другому; бот не принимает чужой callback.

13. РЕАЛИЗОВАННОЕ В 0.1 И ОГРАНИЧЕНИЯ
Реализовано: календарь недели, четыре исходных блока, редактирование/добавление блоков, интервалы и проверки пересечений, шаблон, пошаговое добавление задачи, явная перегрузка, ручные переносы с журналом, фиксация baseline, локальный помодоро, пауза при превышении оценки/границы, итоги и самооценки, экспорт/импорт.
Пока нет: рабочего соединения с Telegram, сервера/входа/синхронизации, автоматических предложений каскадных переносов, отдельного редактора исходных оценок задач, архивирования, исключений событий и буферов, системных фоновых уведомлений. Добавление задачи через кнопки — локальный прототип диалога бота, а не Telegram-интеграция. Публичный GitHub-репозиторий создаётся после доступности аккаунта/инструмента GitHub; локальная папка уже отделена от других проектов.
